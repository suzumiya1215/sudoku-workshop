# 开发记录

技术细节与踩坑清单。写给以后的自己看：**为什么这样写**，而不是重述代码。

---

## 架构

四层，单向依赖，没有循环：

```
core.js    SD.core    位掩码 CSP 内核：约束、候选数、解数计数、变种校验
   ↓
human.js   SD.rate    人类解题技巧阶梯；SD.findStep 找下一步
   ↓
make.js    SD.makePuzzle  出题：生成终盘 → 挖洞 → 控档 → 校验
   ↓
app.js                界面：练习 / 批量 / 手册 / 训练
```

`demo.js` 是数据文件，只被 `app.js` 的手册页读取，不参与出题。

### 数据表示

- 棋盘是长度 81 的 `Uint8Array`，0 表示空。
- 候选数掩码用 **`Uint16Array`**（9 位），`Uint8Array` 会截断第 8、9 位的候选。
- `ctx` 携带变种约束：`regions`（宫划分）、`cages`（笼与和）、`thermos`、`arrows`、`renbans`、`whispers`、`sandwichRows/Cols`、`lks`（小杀手线）。

### 难度

难度 = **解题路径上最难那一步的技巧权重**（SE 的原始定义），不是提示数。

`BANDS` 十档，每档 `{id, name, lo, hi, floor, tech, note}`，`lo/hi` 卡在具体技巧台阶上。`bandOf(se)` 线性查表。

`rate()` 同时返回 `topType` / `topName`，界面「评级依据」用它说明档位是怎么来的——这样档位与步骤的匹配是可验证的，而不是宣称。

## 出题流程

1. `generateFull(ctx, rng)` 随机回溯生成满足变种约束的终盘。
2. `digToBand(ctx, peers, sol, band, rng, opt)` 挖洞。`opt = {floor, cap, fails, deep, deadline}`。
   - 每挖一格用 `countSolutions(..., limit=2)` 验唯一解。
   - `band 2/3` 挖到目标带就 `break`（`deep` 取消），省掉大半 `rate()` 调用。
   - `floor`：L1 = 38 提示，L2–L10 = 21。
3. 挖完 `rate()` 复核；不在档内降一档重试，`depth` 上限 3。

## 踩坑清单

### 出题器

- **`generateFull` 前必须 `setDeadline`**。锯齿数独有不通用例，30 次空转能把单题拖到 11 秒。`generateFull(ctx, rng, 8)` 且 deadline 存在时立即放弃。
- **`cageFeasible` 把「搜索被节点上限截断」当成了「笼不可行」**。4000 节点上限会让 21 提示的杀手题被误判为矛盾，输出 SE 99 的怪题。改为返回 `'skip'` 跳过该次剪枝，`CAP = 30000`。
- **`repairBand` 只补给定，绝不反向挖洞**。反向挖会一路塌回最简题。
- **锯齿布局会失败**。`makeJigsaw` 曾 8 次全失败返回 `null`，而 `makeCtx` 只在 `if (regions)` 时赋值，于是静默保留 3×3 宫——生成了「经典题」却标成锯齿。改为尝试 18 次 + `fixedJigsaw()` 固定合法布局保底，绝不静默退回。
- **杀手笼必须建笼时去重**。`addCages` 生长时若不排除「与本笼已有格同值」的邻居，斜对角会撞值；而 `pruneCages` 对满笼只校验和、不校验重复，非法笼能一路蒙过校验。用 `inCage` 集合在建笼时过滤。
- **单格笼等于给定**，直接丢弃，由挖洞的唯一性校验兜底。

### 评级

- **SE 是离散值**。一个技巧差 0.4 分，L6–L9 区间只有 0.4 宽，贪心挖洞很容易「差半步」停在低一档。试过二次挖洞（换顺序再走一遍），实测没有提升，L9 反而变差，已回退。
- **杀手/混合需要底分**。笼和推理在候选数传播里被当成免费计算，路径 SE 会显示 1.2。加 `CAGE_SE = 2.4`，并在界面明写「路径本身只有 1.2，按底分记 2.4」——不隐藏这个机制。

### 渲染

- **`--cs` 必须设在 `.boardwrap` / `.bgrid` 上**。只设在 `.board` 上时，`.ax` 里的 `calc(var(--cs) * .26)` 全部失效，打印棋盘被撑到 468px（9 格应为 326px）。
- **网格线不能用 CSS border**。打印样式 `.sheet .cell{border-right:.4pt}` 会覆盖，`.cell:nth-child(9n){border-right:0}` 又把右边界清零，导致粗细不一、缺线。改为一条 SVG `path` 画完 8 条细线 + 宫线，`vector-effect: non-scaling-stroke`，打印 0.9 / 1.8pt。
- **SVG overlay 要插在格子之前**。DOM 顺序决定叠放，否则温度计、连续线会压在数字上。数字再用白色 `text-shadow` 描边。
- **杀手笼线要内缩**。`IN = 0.06` 格。不内缩时虚线与网格线重合，肉眼看起来就是「框线断断续续」。
- **`isPrint` 不能靠类型判断**。原来 `typeof cs === 'string'` 当打印标志，改用 CSS 变量后响应式表达式也是字符串，会被误判。改成显式 `opts.print`。
- **答案盘用 `clean: true`**。只留网格和数字，变种辅助线全不画。

### 界面

- **Shift + 数字**：浏览器给的是 `e.key = '#'` / `'@'`，`k >= '1' && k <= '9'` 判不出来，「记候选」这个快捷键一直没生效。改按 `e.code`（`Digit3` / `Numpad3`）取数字。
- **手机打印预览用 `zoom`**。`zoom` 会缩排版尺寸，**不要加负边距**补偿，否则页与页重叠。
- **手册表格列宽用百分比**。固定 `56px + 104px + 210px` 在窄屏把「说明」列挤成一行一个字的竖排。

## 性能

启动曾有一个 **18,852ms 的单一长任务**，来自手册页 13 张示意图在启动时用真实求解器现算。

- 修法一：`tools/make-demo.js` 离线生成 `src/demo.js`（短字段名：`p` 题目 / `s` 解 / `r` 宫 / `cg` 笼 / `th` 温度计 / `ar` 箭头 / `rb` 连续 / `wh` 耳语 / `sr`·`sc` 三明治 / `lk` 小杀手）。
- 修法二：手册页懒加载，首次进入才构建。
- 结果：`goto load` 200–264ms。

## 验证方法

原则：**用数据验证，不用肉眼**。

- **技巧正确性**：遍历 13 种玩法 × 12 道，逐步检查 `place` 的值与 `elim` 是否删到正确答案。当前 156 道错误 0。
- **框线完整性**：导出每块盘的 SVG `path d`，确认细线恒为 `M1 0V9M0 1H9…M5 0V9M0 5H9`、宫线恒为 `M3 0V9M6 0V9M0 3H9M0 6H9`。
- **打印版式**：量 `.sheet` 与棋盘的实际 rect，判断是否越界、页脚是否完整。
- **示意图合规**：`tools/check-demo.js` 按各变种真实判定标准逐条校验。注意口径——连续数独是「一组连续整数、顺序不限」，不是「路径相邻差 1」。
- **演示能否停止**：取盘面快照比对——播放中两次快照应有变化，停止后两次快照应完全一致。
